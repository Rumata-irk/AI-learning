# QA Requirements Workflow

Мультиагентный проект OpenCode: анализ требований → проектирование задач и тестовой модели → проверка результатов → запись и отчёт. Четыре агента разделяют ответственность: `qa-orchestrator`, `requirement-reviewer`, `task-designer`, `test-designer`. Для каждого специалиста подключён отдельный skill.

## Быстрый запуск

Нужны Python 3.10+, OpenCode и настроенная в нём модель с поддержкой вызовов инструментов. В каталоге проекта выполните:

```powershell
python -m pip install -r requirements.txt
opencode
```

Выберите агента `qa-orchestrator`, если он ещё не выбран. Пример запроса:

> Обработай страницу healthchecker-demo проекта DEMO. Создай готовые локальные задачи и тесты, сохрани артефакты и итоговый отчёт. Не выдумывай отсутствующие ожидания.

Изменения конфигурации и агентов вступают в силу после перезапуска OpenCode. Данные примера находятся в `demo/requirements.json`, результаты запуска — в `artifacts/<run-id>/`. Запустите запрос без просьбы создавать записи, чтобы получить только проектирование.

## Рабочий offline demo

До подключения корпоративных MCP можно проверить полный контракт workflow детерминированно:

```powershell
python demo/run_flow.py
```

Скрипт создаёт пример артефактов для страницы `healthchecker-demo` в новом каталоге `artifacts/<run-id>/` со статусом `PARTIAL`.

В OpenCode тот же процесс доступен как команда `/qa-flow` через `.opencode/commands/qa-flow.md`.

## Интеграции

`qa-local` — локальный MCP-сервер на stdio, доступный без аккаунтов. Он читает демонстрационную страницу и записывает локальные задачи и тесты в `demo/store.json`; это не записи Jira или Qase. Повторное создание с тем же проектом и внешним ключом возвращает существующую запись; при несовпадении содержимого возвращается ошибка. Гарантия относится к одному процессу сервера: одновременная работа нескольких серверов с одним файлом не поддерживается.

Для реальных систем подключите MCP-серверы Confluence, Jira и Qase в `opencode.json` или конфигурации пользователя, передайте учётные данные через переменные окружения и сопоставьте доступные операции с workflow. Реальные интеграции в этом проекте не настроены и не проверены. Не добавляйте токены и рабочие требования в Git.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Тест проверяет общение с сервером по MCP stdio, чтение требований, создание, поиск, повторный вызов и обработку ошибки. Проверка работы четырёх LLM-агентов требует установленного OpenCode и доступной модели; результат такого запуска необходимо сохранить отдельно в `artifacts/`.
