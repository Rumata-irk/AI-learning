# Задачи разработки

Область ограничена независимыми требованиями `REQ-HC-001`—`REQ-HC-003` из
review artifact. Поведение при недоступности Prometheus по `P-001` не
проектируется. Точные детали Prometheus, не заданные источником, не
предполагаются.

## TASK-HC-001 — Получение метрики health из Prometheus

- **Цель:** обеспечить получение healthchecker метрики функционального блока
  `marketplace_api.health` из Prometheus.
- **REQ-ID:** `REQ-HC-001`
- **Зависимости:** доступный Prometheus и идентифицируемая метрика
  `marketplace_api.health`; точный контракт источником не задан.
- **Критерии приёмки:**
  1. При доступном Prometheus healthchecker выполняет получение метрики,
     относящейся к функциональному блоку `marketplace_api.health`.
  2. Результат успешного получения доступен последующим операциям
     healthchecker как полученное значение метрики.
- **Незавершённость / вопрос:** не определены точные имя или запрос метрики,
  формат ответа и правила идентификации метрики в Prometheus. Уточнить
  Prometheus-контракт до реализации детального интеграционного сценария.
- **Статус:** `pending_clarification`

## TASK-HC-002 — Опрос с интервалом 60 секунд

- **Цель:** настроить периодический опрос источника метрики с требуемым
  интервалом.
- **REQ-ID:** `REQ-HC-002`
- **Зависимости:** механизм получения метрики из `TASK-HC-001`.
- **Критерии приёмки:**
  1. После запуска healthchecker последовательные плановые опросы выполняются
     с интервалом 60 секунд.
- **Статус:** `pending_clarification` — нужно согласовать допустимое отклонение интервала и учитывать зависимость от `TASK-HC-001`.

## TASK-HC-003 — Сохранение последнего успешно полученного значения

- **Цель:** сохранять последнее значение метрики после успешного получения.
- **REQ-ID:** `REQ-HC-003`
- **Зависимости:** успешное получение метрики из `TASK-HC-001`.
- **Критерии приёмки:**
  1. После успешного получения значения healthchecker сохраняет это значение.
  2. Сохранённое значение доступно как последнее значение метрики после
     завершения успешного получения.
  3. При последовательных успешных получениях сохранённым последним значением
     становится значение, полученное последним.
- **Статус:** `pending_clarification` — нужно определить наблюдаемую точку проверки сохранённого значения и учесть зависимость от `TASK-HC-001`.
- **Ограничение:** способ и место хранения, TTL/очистка и поведение при
  недоступности Prometheus не определяются этой задачей; решение по `P-001`
  заморожено.
