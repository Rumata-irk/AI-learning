## 3. Зависимости между требованиями и внешние зависимости

- REQ-002 → REQ-001: фактический опрос построен на заданном запросе; без корректного запроса нельзя проверить получение.
- REQ-003 → REQ-001, REQ-005: условие «непустое значение» определяет, что именно является успешным получением и, следовательно, что будет сохранено.
- REQ-004 → REQ-001: частота попыток получения метрики определяется интервалом опроса.
- REQ-005 → REQ-003: сохранение происходит только при успешном получении (по REQ-003).
- REQ-006 → REQ-005: значение `last_metric_value` отражает последнее сохранённое значение.
- REQ-007 → REQ-001, REQ-003, REQ-005, REQ-006: правила ошибок определяют поведение всех зависимых сценариев.
- Внешняя зависимость: Prometheus HTTP API (`/api/v1/query`) и конфигурация `prometheus.url`. Контракт ответа не содержится в источнике.
- Внешняя зависимость: клиентский эндпоинт `GET /healthchecker` — схема ответа в источнике не описана.
