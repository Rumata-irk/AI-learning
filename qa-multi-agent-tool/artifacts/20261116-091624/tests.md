### TC-004
- local_id: `TC-004`
- title: Смена `prometheus.url` в конфигурации меняет целевой адрес
- description: |
    Предусловия: два стаба Prometheus — A (`http://a.test:9090`) и B
    (`http://b.test:9090`); конфигурация переключаема между ними.
    Шаги:
    1. Запустить сервис с `prometheus.url = A`, дождаться опроса.
    2. Перезапустить (или применить) конфигурацию с `prometheus.url = B`,
       дождаться опроса.
    Ожидаемый результат: до смены запросы шли только на A, после смены —
       только на B; адрес не захардкожен.
    Примечание: если конфигурация читается только при старте — сценарий
    проверяет перечитывание при рестарте, а не hot-reload.
- req_ids: `REQ-002`
- test_type: `contract` (negative-adjacent: подмена значения для проверки отсутствия хардкода)

### TC-005
- local_id: `TC-005`
- title: Интервал между опросами = 60 с от завершения предыдущего
- description: |
    Предусловия: стаб Prometheus с задержкой ответа `d` (напр. 2 с), метки
    времени входящих запросов и отдаваемых ответов логируются (monotonic clock).
    Шаги:
    1. Запустить сервис, зафиксировать T_end(N) — момент получения ответа
       на опрос N.
    2. Зафиксировать T_start(N+1) — момент прихода опроса N+1.
    3. Повторить для нескольких последовательных циклов.
    Ожидаемый результат: `T_start(N+1) - T_end(N) ≈ 60 с` в пределах
    технического допуска (предлагается ±1 с, `[GAP-2]`); интервал НЕ равен
    `T_start(N+1) - T_start(N)` (это было бы 60+d с).
- req_ids: `REQ-004`
- test_type: `boundary` (time-based; граница = период отсчёта от завершения)

### TC-006
- local_id: `TC-006`
- title: Отсчёт 60 с не накапливает дрейф от времени ответа Prometheus
- description: |
    Предусловия: стаб Prometheus с переменной, имитированной задержкой ответа
    (чередование 1 с и 45 с), логирование таймингов.
    Шаги:
    1. Запустить сервис на ≥3 циклов с разными задержками ответа.
    2. Для каждого N вычислить `T_start(N+1) - T_end(N)`.
    Ожидаемый результат: в каждом цикле разрыв между завершением ответа и
    следующим стартом ≈ 60 с независимо от длительности ответа; при задержке
    45 с период между стартами составляет ≈ 105 с, а не 60 с.
- req_ids: `REQ-004`
- test_type: `boundary` (negative-adjacent: исключает неверную трактовку «от старта»)
