# Проверка передачи контекста между агентами в OpenCode

Оркестратор передаёт субагентам не историю диалога, а пути к артефактам.
Этот документ описывает, как убедиться, что передача действительно
работает.

## Запуск

1. Откройте в OpenCode Desktop каталог `qa-multi-agent-tool`.
2. Перезапустите OpenCode, если менялись агенты, скиллы или `opencode.json`.
3. Выполните `/qa-flow` (или запрос из `.opencode/commands/qa-flow.md`).
4. Разрешите создание demo-записей, только если хотите проверить и запись.

## Признаки корректной передачи контекста

| Проверка | Где смотреть | Ожидание |
|---|---|---|
| Reviewer получил исходник | `artifacts/<run-id>/review.md` | цитаты совпадают с `source.md` дословно |
| Task Designer получил review | `artifacts/<run-id>/tasks.md` | используются те же `REQ-ID`, что в `review.md` |
| Test Designer получил review | `artifacts/<run-id>/tests.md` | те же `REQ-ID` и та же замороженная область |
| Оркестратор проверил артефакты | `artifacts/<run-id>/report.md` | перечислены статусы всех этапов и пути |
| Записи только по готовым | `artifacts/<run-id>/created.json` | нет записей по `drafts` и по `frozen_by` |

Дополнительно: в журнале OpenCode должно быть видно отдельные вызовы
`task` для `requirement-reviewer`, `task-designer` и `test-designer`, а
не один общий ответ оркестратора.

## Признаки проблемы

- `tasks.md` содержит только `REQ-1`, `REQ-2` без соответствия `review.md` →
  субагент не прочитал артефакт, а угадал;
- `tests.md` покрывает замороженные требования → контекст `frozen_scope`
  не передан;
- `created.json` содержит черновики → проверка готовности не сработала;
- в отчёте нет путей к артефактам → оркестратор не валидировал результат.

## Как сохранить подтверждение

Готовый прогон положите в `artifacts/opencode-run/` вместе с кратким
`notes.md`: версия OpenCode, модель, что запускали, какие проверки из
таблицы подтвердились и что осталось под вопросом.
